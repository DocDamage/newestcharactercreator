## Registered body sprite sample: API and desktop

A clean saved prepared character and an existing registered Action can produce a
bounded private sprite sample. The request preserves the complete immutable
project snapshot, every animation reference and the full target binding. Neutral
and facial sprite contracts and their material/reference guards are unchanged.

The desktop starts from the explicit saved-binding selector in **Prepare
registered clip preview…**, then **Render selected saved clip sprites…**. It loads
the complete retained proof in the background. The user selects a local original-
motion record, confirms its declaration and shown qualifications, separately
authorizes every actual source, enters a private-use note, acknowledges the fixed
temporary matte, and chooses a new output folder. No binding or permission is
selected automatically. No technical record-role chooser or image preview is
added.

The full motion remains source frames 2–301 and target frames 1–300 at 30 fps.
The dialog selects 1–32 consecutive target frames and displays source frame
numbers at target+1, image count, sample span and nominal coverage separately.
It offers 128/256px and four fixed directions with level cameras. The broader
backend contract also permits eight directions; actual native eight-direction
coverage is not claimed.

This path needs an unmaterialed source. A request-bound opaque matte, roughness
1 and fixed RGB (0.55, 0.35, 0.25), is applied only on render copies. The background
is transparent; no skin material, texture, master or project revision is adopted.

## Rights, origin and native validation

Every actual rendered source requires its own unchecked per-use sprite grant:
master, expression library, exact registered hand when present, and selected
motion. The accepted native character uses four sources. NoAI, non-UE/private-only
use and no source or sprite redistribution remain fixed. Local preview or engine
permissions never substitute for this new use review.

The origin record is pinned by file SHA and checked against the selected source,
complete snapshot and current catalog policy. Its unique recognized motion role
is derived internally; ambiguous or mismatched records fail. Pre-consent review
uses the actual typed binding, without manufacturing sprite grants or a consented
render request. The qualified historical witness retains the failed original-run
status and independent full-frame recheck. This is an origin declaration, not
cryptographic proof of human authorship or a sprite-rights grant.

Two fresh FBX intake workers authenticate the current source and complete saved
snapshot. Stage and independent verification workers each reconstruct and compare
all 300 source/saved Action frames and render only the selected images. The
four-worker API checks geometry, normals, decoded RGBA pixels, saved-scene
reproduction and atlas crops before exclusive publication. Editable Blender/FBX
sources are not delivered.

The desktop uses the same session catalog, including an explicit `--catalog`,
with no hidden default-library fallback or catalog indexing. Review, rendering
and delivery checks run through the existing single background worker and cancel
Event. Project/catalog/selection changes invalidate authority. Former-dialog
callbacks require both current dialog identity and context token; closing clears
cached binding/request/origin authority. No artificial progress percentages are
reported.

Completion rehashes the closed delivered receipt and exact file inventory off the
GUI thread, including all required atlas sheets. Parsed receipt and recipe bytes
are SHA-bound, four fresh worker identities and the selected Blender identity are
checked, and source/window/readiness scope is retained. Failure notes describing
retained output survive the Qt string boundary. Foreign edits/additions are never
silently relocated by rollback.
