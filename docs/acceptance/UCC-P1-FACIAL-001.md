## Intended behavior and current boundaries

Four saved strengths will control a private expression preview: left and right eyelid closure, mouth corners and mouth opening. Each uses three actual race-specific MPFB 2.0.18 targets already installed locally. Strengths remain between zero and 0.5. The editable master must retain all twelve keys at zero, while preview settings live separately in an explicitly prepared schema-v3 project. Existing projects retain their v1/v2 serialization until preparation. Settings edits and resets must preserve the master and part references; accepting preparation must create one undo step for the entire state transition.

The core preparation contract rejects unchanged master bytes, non-neutral initial intent, unrelated metadata edits and reuse of an old selected-hand manifest. The preparation API first verifies the old selected hand through the normal two-worker same-selection path, including its genuine receipt. It then prepares expression-neutral keys on the original master, builds an actual new hand library through two workers, and reapplies the selected variant through two further workers in a private scratch project with the same character identity and body/face intent. The original hand instance ID is retained. Independently verified immutable original/template masters, reports, assets, manifest and genuine new receipt are installed before one final atomic metadata/master/parts/schema-v3 promotion. Receipts are never relabeled to adopt new hashes. Cancellation or conflicts can leave unreferenced immutable files; they retain the old authoritative pointer and selection. Full project/raw metadata identity, original inputs, installed data, worker outputs, receipts and registered libraries are checked before commit.

Prepared projects now use the composed generation/refit entry points and static-face API. Existing desktop generation/refit routing includes prepared projects even when facial shape settings are empty. Two fresh read-only workers compare all twelve existing keys with independently parsed pinned data before evaluating twenty bounded samples each. Missing/extra keys, even one-ULP coordinate changes, non-neutral values, altered relative keys/settings and master animation reject without repair. Source admission additionally requires the genuine prepared original or registered expression-preservation provenance; selected hands require their compatible library/receipt and normal independent reconstruction. Valid key names alone never authorize adopting an externally rehashed master.

Body refit keeps the actual neutral keys; body generation creates and independently verifies new keys after composing the real body and face. Static-face changes preserve and recheck them. Each changed output receives its own immutable inspection and source/output/library-bound receipt, followed by one final project-pointer commit and one history step. Saved expression strengths remain separate from the neutral keys. A verified static-face no-op creates no revision. The low-level body-only APIs require the composed path, and the existing selected-hand body/face rule still requires restoring Original first. Libraries record initial template provenance rather than falsely approving the current whole body or granting engine/visual quality status.

`ucc.jobs.expression_preparation.prepare_saved_expressions` requires the exact saved project ID, revision and master pointer plus the explicit already-installed MPFB data directory. An already-prepared project rejects before mutation and directs the caller to preview; there is no readiness re-registration shortcut. The content-addressed expression library records initial source intent, the pinned recipe, prepared-original identity, report and neutral observation hashes, with retained source rights. It is provenance for the neutral template, not whole-character approval or a substitute for independently checking future saved Actions/current masters. Loading a changed library, report or provenance master rejects.

The two new internal worker operations stage `expression_human.blend` and independently verify it. They operate only on staged copies and never change project metadata. Closed recipes and protocol options bind the exact source, base, rig and twelve target identities; arbitrary target paths, keys or additional fields are rejected. The stage uses MPFB's real target loader. A separate Blender process manually parses the pinned gzip data, converts MakeHuman coordinates and constructs float32 keys without using that loader. It reproduces the source and all expected keys, compares the complete report, then reopens and observes the saved result before changing any values or refitting. Both reference and saved scenes exercise each unit at 0, 0.25, 0.5, 0.25 and 0, with bounded support/displacement and exact neutral restoration. Original keys, rest rig, skin weights, topology, UVs, materials and unrelated state must remain unchanged.

`ucc.jobs.expression_preview.preview_saved_expressions` now builds a private Action with twelve real shape-key F-curves, each keyed at neutral frame 1, requested peak frame 13 and neutral frame 25, at 24 fps. Its closed recipe binds the complete saved project snapshot, current immutable master, prepared library, four strengths and pinned data. The editable master and project remain unchanged. A fresh worker reconstructs all 25 reference samples from the actual source with independently calculated float32 weights, observes the saved scene and exact Action before changing frames, then checks every reopened frame and every cache byte. Unexpected channels, NLA/drivers, non-linear keys, altered time/fps/binding, unsupported unrelated animation and altered character state reject. The ordinary authoritative-master intake continues rejecting Actions; only the explicitly validated private Key Action is admitted for this preview.

The separate facial cache contract uses the shared immutable GPU buffer type without claiming native-FBX evidence. Every frame retains all 13,380 visible vertices and 26,756 triangles. Polygon topology and original character state remain fixed; Blender may choose pose-dependent diagonals when triangulating deformed quads. Every frame's actual triangle indices are therefore checked against that frame's independent reference. Exact local vertex hashes supplement the shared decoder's quantized skin checks, rejecting even a coherent one-ULP cache forgery. First and last neutral skin positions restore exactly. Combined displacement remains bounded to 30 mm and changes outside declared support to one micrometre. This is precomputed private playback data, not a live morphing UI or visual certification.
