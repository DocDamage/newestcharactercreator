## Objective and constraints

Make UCC derive a bounded wrist correction through its existing fitting action,
without an owner-authored policy or consulting the private T correction file.
Touched modules are candidate policy/search/probe, closed worker protocol,
project-bound transaction, error messages and their unit/integration checks.
The old seven/eight-hash proposal operations remain supported.

The new `propose_native_hand_contact_fit` operation has the same exact eight
hashes as S and declares `BOUNDED_HAND_CONTACT_AREA_SEARCH_V3`. It freshly
reproduces the entire original body-area report and hand/arm surface evidence.
No request override can disable those constraints or expand the budgets.

First find an arm-clear seed using actual skin, joint and strain checks. This
intermediate phase is explicitly not body clearance. Its query dictionary is
isolated and restored even on failure, so an arm-only zero cannot pollute later
body checks. Every actual evaluation counts against the same 1,024-pose limit.

Measure that seed's body constraints on every affected frame. If it needs no
body correction, require a fresh complete verification before returning V1.
Otherwise derive the hand-rotation envelope solely from the observed failing
frames, clamped inside the original changed interval. Test bounded local axes
and angles, learn complete-interval failure frames, then refine wrist offsets
near the most promising measured configurations. No clip frame, bone name,
asset name, correction vector or private policy is embedded in the search.
The existing 30 mm/body-span, 15-degree, speed/acceleration, joint/skin and
helper/rest limits remain enforced. Fewer than 500 trials are allowed; check
trial capacity before each additional query. A failed or exhausted search emits
no partial policy. All final affected-frame checks run fresh with cache disabled.

Core intake requires the new algorithm identifier, retains source/cache/area
receipt checks and independently audits the entire analytic correction before
baking. Saved-Action reproduction, decoded private renders, full fitted cache
and the final two-process body-area guard still precede desktop publication.
Source/master/project SHA checks, revision checks and cancellation remain.
